# rm-socat

**English docs: [README.md](README.md)**

یک ابزار ساده و خودکفا برای فوروارد TCP/UDP روی سرورهای لینوکسی که ترافیک
را به چند سرور بک‌اند ریلی می‌کنند — جایگزین یک ست‌آپ قدیمی مبتنی بر
`crontab @reboot` + `screen` + `socat` که زیر فشار بی‌سروصدا پورت‌هایش
بسته می‌شد. فورواردها زیر `systemd` با `Restart=always` اجرا می‌شوند، توی
چند «دسته» گروه‌بندی شدن (نه یه یونیت جدا برای هر پورت)، و همه‌چیز با یک
دستور/منوی رنگی (`rmsocat`) مدیریت می‌شه که می‌تونه اضافه کنه، حذف کنه،
تست کنه، تحت فشار بگذاره، و کاملاً هرچی که ساخته رو پاک کنه.

## نصب

```bash
curl -fsSL https://raw.githubusercontent.com/Ali-Rahmanii/Rm_Socat/main/install.sh | sudo bash
```

این دستور ریپو را به `/opt/rm-socat` کلون می‌کند، نصب‌کننده‌ی خودش را
اجرا می‌کند، دستور سراسری `rmsocat` را نصب می‌کند، و مستقیم می‌بردت توی
منوی تعاملی. (اگه خودت قبلاً کلون کردی، همون پوشه `cd` کن و `sudo
./install.sh` رو مستقیم بزن — همون اسکریپت، هر دو حالت امنه.) `socat` را
نصب می‌کند، یونیت `systemd` را نصب می‌کند، بار اول `ports.conf` و
`batches.conf` را می‌سازد، و سقف‌های کرنل/`ulimit` را برای کانکشن بالا
بالا می‌برد.

از این به بعد، فقط از هرجا بنویس `rmsocat` تا منو دوباره باز شه. هر بار
که باز می‌شه، یه چک ۲ثانیه‌ای (بدون بلاک کردن) با گیت‌هاب می‌زنه و اگه
نسخه‌ی جدیدتری بود بهت خبر می‌ده. `ports.conf` را ویرایش کن و:

```bash
sudo rmsocat apply
```

## معماری

```
  کاربر ──▶  این سرور (local_port)  ══ socat ══▶  remote_host:remote_port
             نظارت با rm-socat-batch@<batch_id>.service
```

هر قانون در `ports.conf` بر اساس نامش به یکی از تعداد ثابتی از **دسته‌ها**
(`batches.conf`، پیش‌فرض `10`) هش می‌شود. هر دسته یک یونیت `systemd`
(`rm-socat-batch@<id>`) است که `bin/rm-socat-batch-run.sh` را اجرا می‌کند؛
این اسکریپت هر فورواردی که به آن دسته تعلق دارد را به‌عنوان یک پروسه‌ی
`socat` پس‌زمینه بالا می‌آورد (حداکثر یک بار در ثانیه دوباره‌راه‌اندازی
می‌کند اگه بمیره) و اگر یکی مرد، فقط همان یکی را دوباره اجرا می‌کند —
یعنی ده‌ها فوروارد بین چند یونیت مشترک می‌شوند نه یکی برای هر پورت.

نسخه‌ی اول واقعاً به هر پورت یک یونیت `systemd` جدا با `Restart=always`
می‌داد. این مشکل اصلی (بسته ماندن پورت بعد از کرش) را حل کرد، ولی روی
سروری با ۴۰+ فوروارد یک مشکل جدید ساخت: خودِ `systemd` (PID 1) فقط برای
نظارت روی این تعداد یونیت/cgroup سی‌پی‌یوی واقعی مصرف می‌کرد. دسته‌بندی
همون تضمین «پورت مرده خودش برمی‌گردد» را نگه می‌دارد ولی تعداد یونیت را
کم می‌کند — ۱۰ یونیت به‌جای ۹۰.

چون عضویت هر دسته از هش اسم قانون می‌آید، افزودن یا حذف یک قانون هیچ‌وقت
دسته‌ی بقیه را جابه‌جا نمی‌کند — فقط دسته‌ی همان قانون ری‌استارت می‌شود.
دسته‌ها کاملاً مساوی نمی‌شوند — اگه گروه‌بندی ریزتر/بزرگ‌تر می‌خوای،
تعدادش رو با `rmsocat batches` عوض کن.

**یک سوکت هم IPv4 و هم IPv6 را جواب می‌دهد** (پیش‌فرض `ip = dual`). برای
TCP این یعنی `TCP-LISTEN` ساده بدون پسوند؛ برای UDP صراحتاً
`UDP6-LISTEN` است — چون بعضی نسخه‌های socat با `UDP-LISTEN` بدون
family مشخص کرش می‌کنند (`unknown address family 0`)، UDP همیشه
family‌اش را صریح می‌گوید و با `net.ipv6.bindv6only=0` (که `install.sh`
تنظیمش می‌کند) باز هم کلاینت‌های IPv4 را قبول می‌کند. برای مجبور کردن به
یک خانواده، `ip = 4` یا `ip = 6` بگذار.

بدون لاگ‌گیری: همه‌ی یونیت‌ها با `StandardOutput=null` /
`StandardError=null` اجرا می‌شوند.

## فرمت `ports.conf`

```
name , local_port , remote_host , remote_port , proto , ip
```

| فیلد          | معنی                              | مقادیر                        |
|---------------|-------------------------------------|----------------------------------|
| `name`        | شناسه‌ی یکتا، پایه‌ی هش دسته        | `[A-Za-z0-9_-]+`                |
| `local_port`  | پورتی که این سرور گوش می‌دهد        | `1-65535`                       |
| `remote_host` | دامنه یا آی‌پی مقصد                 | هرچیزی                          |
| `remote_port` | پورت روی `remote_host`              | `1-65535`                       |
| `proto`       | چه سوکت‌هایی باز شود                | `tcp` \| `udp` \| `both`        |
| `ip`          | خانواده‌ی آدرس                      | `dual` (پیش‌فرض) \| `4` \| `6`  |

جزئیات و مثال در [`ports.conf.example`](ports.conf.example). **هم
`ports.conf` هم `batches.conf` در `.gitignore` هستند** — نه دامنه/آی‌پی
واقعی‌ات، نه تعداد batch انتخابیت، هیچ‌وقت با `git pull` تداخل پیدا
نمی‌کنند.

فقط فورواردی که واقعاً به UDP نیاز دارد باید `proto=both` باشد — یک
تانل SSH یا کانفیگ V2ray روی TCP/WS نیازی به آن ندارد، و هر سوکت UDP
اضافه فقط یه چیز دیگه‌ست که بی‌دلیل می‌تونه fail بشه.

## استفاده

```bash
rmsocat                     # منوی رنگی تعاملی
rmsocat add                 # افزودن قانون
rmsocat remove <name>       # حذف قانون، ری‌استارت دسته‌اش
rmsocat apply               # هماهنگ‌سازی همه‌ی دسته‌ها با ports.conf
rmsocat status              # جدول زنده: وضعیت دسته + وضعیت واقعی سوکت
rmsocat restart             # ری‌استارت همه‌ی دسته‌ها
rmsocat test                # تأیید باز بودن همه‌ی پورت‌ها
rmsocat stress <port> [tcp|udp] [step] [settle] [max] [hold] [host]
rmsocat batches              # تغییر تعداد یونیت‌های systemd
rmsocat update                # git pull (با stash خودکار تغییرات محلی) + اعمال دوباره
rmsocat purge                  # پاکسازی کامل
```

## به‌روزرسانی

```bash
sudo rmsocat update
```

هر تغییر محلی را موقتاً کنار می‌گذارد (`stash`)، آخرین کامیت را می‌کشد
(فقط fast-forward)، تغییرات محلی را برمی‌گرداند، اسکریپت‌ها را دوباره
اجرایی می‌کند، یونیت `systemd` را (اگه عوض شده بود) دوباره نصب می‌کند، و
`ports.conf` را روی همه‌ی دسته‌ها اعمال می‌کند.

## تست‌ها

- `rmsocat test` — همین الان همه‌ی پورت‌ها واقعاً `LISTEN` هستند؟
- `rmsocat stress <port> [tcp|udp] [step] [settle] [max] [hold] [host]` —
  با bash خالص، همه‌ی کانکشن‌های بازشده را **همزمان** باز نگه می‌دارد
  (نه باز-و-بسته‌ی پی‌درپی) و پله‌پله بالا می‌برد، پس عددی که گزارش
  می‌شه واقعاً همزمانیه نه تجمعی. اول `ulimit` خودِ شل رو بالا می‌بره —
  معمولاً همون سقف واقعیه، نه خودِ پورت. **کل زنجیره تا سرور مقصد واقعی
  را زیر فشار می‌گذارد**، تأیید لازم دارد.

## پاکسازی کامل

```bash
sudo rmsocat purge      # یا: sudo ./uninstall.sh
```

همه‌ی یونیت‌های دسته را متوقف/حذف می‌کند (اگه `disable` fail کرد،
مستقیم فایل یونیت/لینک‌های enable رو هم پاک می‌کند، به‌علاوه
`systemctl reset-failed` و یک `pkill -x socat` به‌عنوان آخرین راه‌حل)،
یونیت الگو، drop-inهای sysctl/limits، و دستور `rmsocat` را پاک می‌کند، و
در آخر با یک تأیید جدا («بنویس YES») می‌پرسد که کل پوشه هم حذف شود —
چیزی باقی نمی‌ماند.
