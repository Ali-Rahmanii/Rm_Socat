# rm-socat

**English docs: [README.md](README.md)**

یک ابزار ساده برای فوروارد TCP/UDP روی سرورهای لینوکسی که ترافیک را به چند
سرور بک‌اند ریلی می‌کنند — جایگزین یک ست‌آپ قدیمی مبتنی بر `crontab
@reboot` + `screen` + `socat` که زیر فشار بی‌سروصدا پورت‌هایش بسته می‌شد.
فورواردها زیر `systemd` با `Restart=always` اجرا می‌شوند، پس اگر `socat`
کشته شود حدود ۱ ثانیه بعد برمی‌گردد.

## معماری

```
  کاربر ──▶  این سرور (local_port)  ══ socat ══▶  remote_host:remote_port
             نظارت با rm-socat-batch@<batch_id>.service
```

هر قانون در `ports.conf` بر اساس نامش به یکی از تعداد ثابتی از **دسته‌ها**
(`batches.conf`، پیش‌فرض `10`) هش می‌شود. هر دسته یک یونیت `systemd`
(`rm-socat-batch@<id>`) است که `bin/rm-socat-batch-run.sh` را اجرا می‌کند؛
این اسکریپت هر فورواردی که به آن دسته تعلق دارد را به‌عنوان یک پروسه‌ی
`socat` پس‌زمینه بالا می‌آورد و اگر یکی مرد، فقط همان یکی را دوباره اجرا
می‌کند — یعنی ده‌ها فوروارد بین چند یونیت مشترک می‌شوند نه یکی برای هر
پورت.

نسخه‌ی اول واقعاً به هر پورت یک یونیت `systemd` جدا با `Restart=always`
می‌داد. این مشکل اصلی (بسته ماندن پورت بعد از کرش) را حل کرد، ولی روی
سروری با ۴۰+ فوروارد یک مشکل جدید ساخت: خودِ `systemd` (PID 1) فقط برای
نظارت روی این تعداد یونیت/cgroup سی‌پی‌یوی واقعی مصرف می‌کرد. دسته‌بندی
همون تضمین «پورت مرده خودش برمی‌گردد» را نگه می‌دارد ولی تعداد یونیت را
کم می‌کند — ۱۰ یونیت به‌جای ۹۰.

چون عضویت هر دسته از هش اسم قانون می‌آید، افزودن یا حذف یک قانون هیچ‌وقت
دسته‌ی بقیه را جابه‌جا نمی‌کند — فقط دسته‌ی همان قانون ری‌استارت می‌شود
(و هرچی دیگه توی همون دسته باشه هم یه لحظه قطع می‌شه). دسته‌ها کاملاً
مساوی نمی‌شوند (هش کردن ~۴۵ اسم توی ۱۰ دسته معمولاً بین ۲ تا ۹ در هر
دسته می‌افتد، نه دقیقاً ۴ یا ۵) — اگه گروه‌بندی ریزتر/بزرگ‌تر می‌خوای،
تعدادش رو با `./manage.sh batches` عوض کن.

**یک سوکت هم IPv4 و هم IPv6 را جواب می‌دهد** (پیش‌فرض `ip = dual` —
`TCP-LISTEN`/`UDP-LISTEN` بدون پسوند `4`/`6`). نیاز به
`net.ipv6.bindv6only=0` دارد که `install.sh` خودش تنظیمش می‌کند. برای
مجبور کردن به یک خانواده، `ip = 4` یا `ip = 6` بگذار.

بدون لاگ‌گیری: همه‌ی یونیت‌ها با `StandardOutput=null` /
`StandardError=null` اجرا می‌شوند — در حالت عادی چیزی به journal یا دیسک
نوشته نمی‌شود.

## فرمت `ports.conf`

```
name , local_port , remote_host , remote_port , proto , ip
```

| فیلد          | معنی                              | مقادیر                        |
|---------------|-------------------------------------|----------------------------------|
| `name`        | شناسه‌ی یکتا، پایه‌ی هش دسته        | `[A-Za-z0-9_-]+`                |
| `local_port`  | پورتی که این سرور گوش می‌دهد        | `1-65535`                       |
| `remote_host` | دامنه یا آی‌پی مقصد                 | هرچیزی                          |
| `remote_port` | پورت روی `remote_host`              | `1-65535`                       |
| `proto`       | چه سوکت‌هایی باز شود                | `tcp` \| `udp` \| `both`        |
| `ip`          | خانواده‌ی آدرس                      | `dual` (پیش‌فرض) \| `4` \| `6`  |

جزئیات و مثال در [`ports.conf.example`](ports.conf.example). خودِ
`ports.conf` در `.gitignore` است — دامنه/آی‌پی واقعی هیچ‌وقت کامیت
نمی‌شود، فقط نمونه‌اش کامیت شده.

## نصب

```bash
curl -fsSL https://raw.githubusercontent.com/Ali-Rahmanii/Rm_Socat/main/install.sh | sudo bash
```

این دستور ریپو را به `/opt/rm-socat` کلون می‌کند و نصب‌کننده‌ی خودش را
اجرا می‌کند. (اگه خودت قبلاً کلون کردی، همون پوشه `cd` کن و `sudo
./install.sh` رو مستقیم بزن — همون اسکریپت، هر دو حالت امنه.) `socat` را
نصب می‌کند، یونیت `systemd` را نصب می‌کند، بار اول `ports.conf` و
`batches.conf` را می‌سازد، و سقف‌های کرنل/`ulimit` را برای کانکشن بالا
بالا می‌برد.

بعد `ports.conf` را ویرایش کن و:

```bash
sudo /opt/rm-socat/manage.sh apply
```

## استفاده

```bash
./manage.sh                 # منوی رنگی تعاملی
./manage.sh add             # افزودن قانون
./manage.sh remove <name>   # حذف قانون، ری‌استارت دسته‌اش
./manage.sh apply           # هماهنگ‌سازی همه‌ی دسته‌ها با ports.conf
./manage.sh status          # جدول زنده: وضعیت دسته + وضعیت واقعی سوکت
./manage.sh restart         # ری‌استارت همه‌ی دسته‌ها
./manage.sh test            # تأیید باز بودن همه‌ی پورت‌ها
./manage.sh stress <port> [tcp|udp] [step] [hold] [max]
./manage.sh batches         # تغییر تعداد یونیت‌های systemd
./manage.sh update          # git pull + اعمال دوباره
./manage.sh purge           # پاکسازی کامل
```

## به‌روزرسانی

```bash
sudo ./manage.sh update
```

آخرین کامیت را می‌کشد، اسکریپت‌ها را دوباره اجرایی می‌کند، یونیت
`systemd` را (اگه عوض شده بود) دوباره نصب می‌کند، و `ports.conf` را روی
همه‌ی دسته‌ها اعمال می‌کند. نیاز به این دارد که نصب از طریق git باشد —
همون نصب یک‌خطی بالا خودش این را فراهم می‌کند.

## تست‌ها

- `./manage.sh test` — همین الان همه‌ی پورت‌ها واقعاً `LISTEN` هستند؟
- `./manage.sh stress <port> [tcp|udp] [step] [hold] [max]` — با bash خالص
  کانکشن همزمان را بالا می‌برد تا سقف واقعی را پیدا کند. **کل زنجیره تا
  سرور مقصد واقعی را زیر فشار می‌گذارد**، تأیید لازم دارد.

## پاکسازی کامل

```bash
sudo ./manage.sh purge      # یا: sudo ./uninstall.sh
```

همه‌ی یونیت‌های دسته را متوقف/حذف می‌کند، یونیت الگو و drop-inهای
sysctl/limits را پاک می‌کند، و در آخر با یک تأیید جدا («بنویس YES»)
می‌پرسد که کل پوشه هم حذف شود — چیزی باقی نمی‌ماند.
